# GROME — контекст для следующей сессии

## Рабочий контур

- Канонический код: GitHub `master`.
- Локальная работа: один клон проекта для Codex Desktop и CLI; при параллельных задачах — отдельные ветки/worktree.
- Production: только результат GitHub Actions. Данные и секреты остаются на VPS.

## Как продолжать

1. Перед задачей синхронизировать локальную ветку с `master` и прочитать `AGENTS.md`.
2. Выполнить изменения и подходящие тесты.
3. Обновить этот файл кратким итогом: задача, SHA, проверки, известные ограничения.
4. После merge релизный workflow фиксирует SHA в `.release-version` на VPS.

## Текущая точка

- Ветка подготовки: `baseline-sync`.
- В ней есть базовая сверка production-кода и исправление мобильного расположения фильтра дат ОВН.
- Контракт единого релиза добавлен в текущем commit ветки; единственный production workflow — `.github/workflows/deploy.yml`, запускаемый push в `master`. Устаревший параллельный workflow удалён и его отсутствие контролирует регрессия.
- Перед публикацией проверены: синтаксис серверных и критичных клиентских JS-файлов, adapter truth, расписание, аналитика ОВН, мобильный фильтр и контракт релиза.
- Следующий шаг: опубликовать текущий проверенный baseline как GitHub `master`; Actions доставит тот же SHA на production-VPS и зафиксирует его в `.release-version`.
